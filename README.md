# KeyMouse Overlay —— 按 SVG 设计稿渲染的键鼠显示

![预览](preview.png)

透明浮层版的键鼠显示：**形状、圆角、字重、鼠标轮廓全部来自 SVG 设计稿**。
程序直接解析 SVG 路径（含贝塞尔曲线、圆角、字形路径、transform 矩阵）再栅格化，
不是照着图猜坐标。**不需要 OBS，也不需要 NohBoard**。

内置三套可随时切换的布局：

- **经典布局**：保留原来的 Q W E、Shift A S D、Ctrl、空格和鼠标。
- **扩展布局**：增加 1–4、Tab、R、F、Alt、Z X C V，保留经典布局已有的全部按键。
- **五列布局**：在扩展布局基础上再加一列，增加 5、T、G、B，键位覆盖 Q–T / A–G / Z–B。

扩展布局实际效果（W 键与鼠标左键按下）：

经典布局加 `--bg` 就是设计稿里那张黑底卡片：

## 怎么做到的

`keyoverlay.py` 里有一个小型 SVG 解析器，只做四件事：

1. 递归遍历 `<g>`，继承 `fill / stroke / stroke-width`，累积 `transform`；
2. 把 `M L H V Q C Z`（含相对指令）展平成折线，曲线按 8 段采样；
3. `<rect rx>` 转成圆角多边形；
4. 每个元素单独栅格化并缓存成小贴片，按下时换一份"黄底"版本。

所以以后改设计只要改 SVG，不用动代码。

## 元素 → 按键映射

| SVG id            | 按键      | SVG id                  | 按键       |
| ----------------- | ------- | ----------------------- | -------- |
| `key-q` ~ `key-e` | Q W E   | `key-a` ~ `key-d`       | A S D    |
| `key-shift`       | 左 Shift | `key-ctrl`              | 左 Ctrl   |
| `key-space`       | 空格      | `mouse-left/right`      | 左/右键     |
| `mouse-wheel`     | 中键      | `mouse-side-front/back` | 侧键 X1/X2 |

扩展布局另使用 `key-1` ~ `key-4`、`key-tab`、`key-r`、`key-f`、`key-alt`、`key-z` ~ `key-v`，对应数字键、Tab、R、F、Alt 和 Z X C V。五列布局再增加 `key-5`、`key-t`、`key-g`、`key-b`，对应数字 5、T、G、B。左右 Shift、Ctrl、Alt 都能点亮同一个修饰键图标。

字母标签按 `aria-label` 关联到对应按键，按下时键帽变黄、字母保持白色。

## 用法

```
双击 start.bat                     # 默认：左下角、1.2 倍、点击穿透、透明底
```

| 参数                                    | 说明                               |
| ------------------------------------- | -------------------------------- |
| `--scale 1.2`                         | 整体缩放（经典布局 1.0 时约 420×186）      |
| `--layout classic` / `extended` / `wide` | 指定启动布局：经典 / 扩展 / 五列            |
| `--no-panel`                          | 启动时不打开控制面板                       |
| `--bg`                                | 连 SVG 的黑色底板一起画（就是设计稿那张图）         |
| `--mouse-yellow`                      | 鼠标左右键**常亮**黄色（不要按下反馈时用，更接近设计稿）   |
| `--pos 40,900`                        | 指定左上角坐标；不给就自动左下角                 |
| `--margin 40`                         | 左下角时的边距                          |
| `--solid`                             | 取消点击穿透                           |
| `--preview out.png`                   | 只出图不开窗口，可配 `--pressed W,LMB`     |
| `--hold 0.03`                         | 按下后**至少点亮**多少秒（默认 0.03）          |
| `--poll 0.006`                        | 轮询间隔（默认 6ms）                     |
| `--debug`                             | 把每次状态变化写进 `keyoverlay.log`，排查连点用 |
| `--no-tray`                           | 不创建系统托盘图标                        |
| `--toggle-vk 0x78` / `--quit-vk 0x7A` | 显示/隐藏、退出热键的虚拟键码（写 `0` 或 `none` 表示禁用） |
| `--move-vk 0x77`                      | 移动浮窗的按键（默认 F8）                     |

运行中：**F9 显示/隐藏，F10 退出，F8 拖动位置**，缩放和布局在**控制面板**里点一下就行。

### 快捷键冲突怎么办

**默认只认"光按一个键"**：按住 Alt / Ctrl / Shift / Win 时，热键不触发。
所以 NVIDIA 录屏用的 `Alt+F9` **不会**再把浮层隐藏（这是 issue #1 的修复）。

如果还想彻底改掉或关掉：

- **控制面板 → 快捷键**：两个下拉框分别设「显示/隐藏」和「退出程序」，
  可选 F6 / F7 / F9 / F10 / F11 / F12 / ScrollLock / Pause / Insert / Home / End / PageUp / PageDown / ` / [ / ]，
  选「**禁用**」就完全不响应。改完立即生效，并存进 `overlay.json`。
- **命令行**：`--toggle-vk 0x77`（改成 F8）、`--toggle-vk 0`（禁用）。
  命令行优先级高于面板设置。

> 「显示/隐藏」和「退出程序」不能设成同一个键（都选「禁用」除外）。
> 面板里选到冲突键会自动退回并提示；命令行传入相同键会直接报错，旧配置里的冲突会自动禁用退出热键。
>
> F8 留给「移动浮窗」，不在可选列表里，避免两个功能抢同一个键。

### 缩放大小

控制面板里有一行「缩放」：`−` / `＋` 每次 10%，中间显示当前倍率（如 120%），`重置` 回到 100%。
范围限制在 70%～240%，**以左下角为锚点**缩放；即使已经拖动过浮窗，缩放后也不会跳回默认位置。

倍率会存进 `overlay.json`，下次启动沿用；想临时指定用 `--scale 1.5`。

> 缩放是**按新尺寸重新矢量渲染**，不是把画面拉大，所以放大后边缘依然是干净的。
> 每按一次要重绘一遍，约 40～150ms（倍率越大越慢），只会卡这一下。

### 移动浮窗位置

浮窗平时是**点击穿透**的（鼠标点不进去，这样才不会挡着游戏），所以不能直接拖。三种办法：

1. **按 F8**（或点面板上的「移动浮窗」）—— 浮窗四周出现虚线框、鼠标变成十字箭头，
   **按住左键就能拖**；再按一次 F8 回到穿透状态。
   松手时位置会存进 `overlay.json`，**下次启动自动回到这里**。
2. **托盘右键 → 关闭穿透**（`--solid` 启动时也可以）——不常用，会一直挡鼠标。
3. **命令行指定**：`KeyOverlay.exe --pos 100,200`（左上角坐标，优先级高于记忆的位置）。

> `overlay.json` 还会记住上次用的**布局**，所以「拖好位置 + 选好布局」重启后都会保持。
> 切换布局或缩放时也以**当前左下角**为锚点，拖好的位置不会因为换布局而回到初始位置。
> 想恢复默认位置，删掉 `overlay.json` 或加 `--pos` 即可。

### 鼠标滚轮

滚轮不再只有"按下才亮"这一种状态了：

| 操作 | 显示 |
|---|---|
| **上滚** | 滚轮**上半**变黄 |
| **下滚** | 滚轮**下半**变黄 |
| **按下中键** | 整个滚轮变黄（和以前一样，优先级最高） |

一次滚格亮 70ms，连滚就是一串"上上上"。方向靠 **Raw Input**（`RIDEV_INPUTSINK`）拿的：
它只是复制一份鼠标事件给我们，**不拦截、不给系统输入加延迟**，比低层钩子干净。

### 控制面板与布局切换

用**脚本**（`start.bat`）启动时会自动打开控制面板；**双击 exe 不会弹面板**（不打扰你），
右键托盘图标 →「打开控制面板」随时都能叫出来。想强制打开加 `--panel`，想彻底不建加 `--no-panel`。

面板里能做的事：可直接选择「经典布局」「扩展布局」或「五列布局」，也可隐藏/显示浮层、退出程序。关闭面板窗口只会收起面板，不会退出浮层；之后可从托盘右键菜单重新打开。

托盘右键菜单也提供三种布局的直接切换。切换会立即重绘，不需要重启，原来的 `keyboard-mouse.svg` 不会被修改。

> 重复双击 `start.bat` 不会叠出两个浮层：新实例会先让旧实例退出再接管。

### 系统托盘

启动后任务栏右下角会有一个图标（就是程序自己的键盘/鼠标图标）：

| 操作       | 效果                     |
| -------- | ---------------------- |
| **左键单击** | 显示 / 隐藏浮层              |
| **右键**   | 菜单：隐藏浮层 / 重新加载设计稿 / 退出 |

托盘图标的状态会跟着变：悬停提示会显示「显示中」还是「已隐藏」。

> **Windows 11 会把新图标默认收进 `^` 折叠区**，看不到就点一下 `^`，  
> 把它**拖到**任务栏上，以后就一直显示了。这是系统行为，程序没法自己把它"钉"出来。

「重新加载当前设计稿」用于修改当前布局的 SVG 后热重载：经典布局对应 `keyboard-mouse.svg`，扩展布局对应 `keyboard-mouse-extended.svg`，五列布局对应 `keyboard-mouse-wide.svg`。

### 进游戏后浮层看不见 / 按键不亮？

**首要原因：游戏是「以管理员身份运行」的，浮层必须跟它同权限。**

游戏一旦提权运行，它的窗口就处在**高完整性级别**，而普通双击启动的 KeyOverlay 在**中完整性级别**，
Windows 的 UIPI（用户界面特权隔离）会在两者之间竖一道墙，于是同时坏两件事：

| 现象 | 真实原因 |
| --- | --- |
| 浮层整个看不见，像被游戏盖住 / 只在切出游戏时闪一下 | 低权限进程的置顶窗口压不到高权限窗口上面 |
| 浮层看得见，但怎么按都不亮 | 前台是高权限窗口时，输入读不进来 |

两者都是权限不对等造成的，**跟 SVG、缩放、`--hold`、热键统统无关**，调参数是白费功夫。

**解决：让浮层和游戏一样提权。**

1. **一次性**：右键 `KeyOverlay.exe`（`dist\` 里的，或从 Releases 下的那个）→ **以管理员身份运行**。
2. **一劳永逸**：右键 exe → 属性 → **兼容性** → 勾选 **以管理员身份运行此程序** → 确定。以后双击就是管理员。
3. **用源码跑 `start.bat` 的**：它启动的是 `pythonw.exe`，**改 exe 的属性管不到它**，得单独处理——
   右键 `start.bat` 同样勾上兼容性里的"以管理员身份运行"（或右键 → 以管理员身份运行）。
4. 想固定参数就用快捷方式：右键 → 属性 → 快捷方式 → **高级** → 勾选 **用管理员身份运行**。

几点值得知道的：

- **提权一定会弹 UAC**，除非把 UAC 关了（不建议）。这是系统设计，程序绕不过去。
- **浮层提权后照样兼容不提权的游戏**：高权限能覆盖低权限，反过来不行。
  所以懒人做法是「**浮层永远以管理员启动**」，两种情况都覆盖。
- **F9 / F10 提权后仍然有效**：本程序用 `GetAsyncKeyState` 轮询而不是 `RegisterHotKey`，
  不依赖窗口焦点，提权不受影响。
- **别急着给游戏提权**：能不提就不提。游戏本身不需要管理员权限的话，直接普通启动最省事。

**先分清是哪种"不亮"**：

```
KeyOverlay.exe --debug
```

按一下 W，然后看 `keyoverlay.log`：

- **有记录** → 按键读到了，只是浮层被盖住 → 查权限（就是上面这条）或把游戏改成**无边框窗口**。
- **没记录** → 输入根本没进来 → 100% 是权限不对等，提权重启浮层。

顺带一句：如果游戏是**独占全屏**，即便权限一样也看不见（见「已知限制」第 1 条），要切成**无边框窗口**。

### F10 按了没退出？

**旧版本这里是真 bug**：代码里把退出热键写成 `0x7A` 并标成 F10，但 `0x7A` 其实是 **F11**（F10 是 `0x79`）。  
所以以前按 F10 毫无反应、按 F11 才退。现在默认 `F10 和 F11` 都认。

如果还是不行：

1. **笔记本的 F10 可能是多媒体键**，要按 `Fn+F10`。也可以换键：
   ```
   --quit-vk 0x77     F8 退出
   --quit-vk 0x7B     F12 退出
   ```
2. 确认没有多个旧实例 —— **双击 `stop.bat`** 一次清干净（按窗口类名找，不依赖热键）。
3. 确认改的是 `start.bat` 启动的那个进程（不是别的 python 脚本）。

### 连点只闪一下就没了？

点亮时长由 `--hold` 决定（默认 60ms）。`--hold` 越长，两次点击之间的“熄灭间隙”越容易被吃掉。  
所以：

- **想看清楚每一次快速点按** → 调大：`--hold 0.08`
- **想更灵敏、连点分得更开** → 调小：`--hold 0.03`（再小也看不出区别，见下）

实测（按 25ms、间隔 90ms 点两下）：

```
--hold 0.15  -> 一段连续亮灯（看起来只闪一下）
--hold 0.06  -> W 亮 87ms → 灭 29ms → W 亮 87ms
--hold 0.03  -> W 亮 34ms → 灭 81ms → W 亮 49ms（三下连点，三下都清楚分开）
```

注意：一次重绘本身要 ~~30ms，所以 `--hold` 调到 0.03 以下，「亮」的时长基本就卡在 30~~40ms 不再变短，  
只是熄灭间隙更干净。再往下调没有实际收益。

调完可以用 `--debug` 启动，然后 `keyoverlay.log` 里就是每次亮/灭的时间戳，方便对着调。

### 按 F9 没反应？

1. 先确认只剩一个浮层（旧版本可能叠了多个）——结束所有 `pythonw.exe` 再启动。
2. 笔记本的 F9 可能是多媒体键，试 `Fn+F9`，或换键：`--toggle-vk 0x77`（F8）。
3. F9 只是隐藏，进程还在；彻底退出按 **F10**。

### 键盘像被按住 / 滚轮变成缩放？

典型症状：打字全是快捷键效果、全变成大写，或者滚轮一滚页面就放大缩小。  
这是 **Ctrl / Shift / Alt / Win 卡成了"按下"状态**（Ctrl 卡着时，滚轮就是缩放）。

**双击 `release_keys.bat`** 即可——它只补发"抬起"，从不发送"按下"，可以放心双击。

它做两件事：

1. 给全部虚拟键码 + 鼠标按键补发抬起（治系统层的卡键）；
2. **再直接给当前前台窗口投递一遍 `WM_KEYUP`**（治「系统已经松开、但那个程序自己还以为按着」）。

> **为什么需要第 2 步**：按键消息只发给**当时的前台窗口**。如果那个"记着 Ctrl 按着"的程序  
> 在补发抬起时不在前台，它就永远不知道键已经松了——这时 `GetAsyncKeyState` 查起来是干净的，  
> 但你就是打不了字。遇到这种情况，**先点一下出问题的那个窗口让它到前台，再双击一次**。

> 说明：**浮层程序本身只读取按键状态（GetAsyncKeyState），从不注入任何按键**，不会造成卡键。  
> 这种情况通常来自按键注入类脚本被中途杀掉（按下了却没来得及发抬起）、  
> 或者宏软件把某个键卡在持有状态。

## 改设计

- **改形状/字**：经典布局改 `keyboard-mouse.svg`，扩展布局改 `keyboard-mouse-extended.svg`，五列布局改 `keyboard-mouse-wide.svg`（Illustrator / Figma / Inkscape 都行），程序启动时重新解析。
- **改高亮色**：`keyoverlay.py` 顶部 `HILITE`（默认取自 SVG 黄色渐变的中间色 `#e9df68`）。
- **关掉外发光/投影**：`GLOW = False` / `SHADOW = False`。
- **改整体大小**：`ART_SCALE`（SVG 单位 → 像素，默认 0.34）或直接用 `--scale`。

### 扩展布局的设计稿

`keyboard-mouse-extended.svg` 是**手工绘制的正式稿**，字母用的是真字体轮廓路径，
键帽尺寸、键距、鼠标比例都按参考图定的。改它直接改这个文件即可。

`make_extended_svg.py` 是一个**备选方案生成器**（不是正式稿的来源）：手写 SVG 时如果
不想自己画 21 个键帽，可以用它按参数批量生成，字母由 fontTools 从 Windows 自带字体
转成轮廓。它的默认输出是 `keyboard-mouse-extended-generated.svg`，**不会覆盖正式稿**。

```
python make_extended_svg.py                       # 生成 keyboard-mouse-extended-generated.svg
python make_extended_svg.py out.svg               # 输出到别的文件
python make_extended_svg.py out.svg --font="C:\Windows\Fonts\arialbi.ttf"
```

脚本顶部可调：`FONT_PATH`（字体）、`KEY_W/KEY_H/SKEW/RADIUS`（键帽）、`PITCH_X/PITCH_Y`（键距）、
`LETTER_STROKE_RATIO`（字母描边粗细）、`LETTER_FILL`（`"none"` 空心 / `"#f5f5ef"` 实心）。

### 五列布局的设计稿

`keyboard-mouse-wide.svg` 在扩展布局基础上增加第五列：键帽、鼠标、数字 1–4 以及
Q W E R / A S D F / Z X C V 等字形全部复用扩展布局，只补了 5、T、G、B 四个字形和第五列键位。

- 想换设计稿：把改好的 `keyboard-mouse.svg` **放在 exe 同一个目录**，它会优先用这一份  
  （不放就用内嵌的那份）。
- 重新打包：双击 `build_exe.bat`（会自动装 PyInstaller，约 20 秒出结果），产物在本地 `dist\`。

两个实话：

1. **单文件版首次启动约 2.2 秒**——它要先把自己解压到临时目录。嫌慢可以改成目录版  
   （`build_exe.bat` 里把 `--onefile` 去掉），启动约 0.6 秒，但会产出个文件夹。
2. **exe 没有数字签名**，第一次运行 Windows SmartScreen 可能拦一下（“更多信息 → 仍要运行”），  
   个别杀软也会对 PyInstaller 打包的 exe 误报。这是打包方式决定的，不是程序有问题。

## 资源占用（实测）

在 i5/16 线程笔记本上，单文件 exe 版实测（Windows 11，屏幕 2560×1600 @125%）：

| 场景 | CPU（单核占比） | 内存（工作集） | GDI 对象 | 句柄 |
|---|---|---|---|---|
| 空闲待机 | **3.5%** | 49.8 MB | 11 | 167 |
| 连续快速滚轮（约 30 次/秒） | 8.9% | 52.1 MB | 11 | 167 |
| 挂 10 分钟后 | 3.7% | 52 MB（不增长） | 11 | 167 |

exe 是 PyInstaller 单文件版，会有两个进程：引导器 8.9 MB + 真正的程序 49.8 MB，**合计约 59 MB**。
用 `start.bat` 跑脚本版约 41 MB（少了打包的运行时）。

> 3.5% 是**单核占比**。这台机器 16 线程，折算成整机 CPU 约 0.2%。
> 如果嫌费电，加 `--poll 0.012`：实测空闲降到 **0.9%**，代价是按键响应慢约 6ms。
> 只想要按键不要滚轮方向，可以加 `--no-wheel`。

### 为省 CPU 做的三处优化

1. **只轮询当前布局画了的键**：经典布局 11 个键、扩展布局 24 个，不再固定轮询全部 29 个。
2. **滚轮改用 Raw Input 批量读取**（`GetRawInputBuffer`）：鼠标一秒能发上千条移动事件，
   逐条走系统调用太重，改成一轮读一批、按字节解析。
3. **滚轮解析不建对象**：用 `struct.unpack_from` 直接读字节，不给每条事件创建 ctypes 结构体。

## 已知限制

1. **独占全屏游戏里看不到**，游戏要设"无边框窗口"。
2. 用 `GetAsyncKeyState` 轮询（12ms），**不装全局钩子**，对反作弊友好；最快按键会延迟一帧。
3. 状态切换时才重绘（约 30ms，相同状态走缓存），连续快速按键不会卡。
4. 录屏要录**整个屏幕**，别选单窗口，否则浮层录不进去。
5. **游戏以管理员启动时，KeyOverlay.exe 也要以管理员启动**——见上文「[进游戏后浮层看不见 / 按键不亮？](#进游戏后浮层看不见--按键不亮)」，
   这是浮层失效的头号原因。懒人做法：永远给浮层提权，两种情况都兼容。
